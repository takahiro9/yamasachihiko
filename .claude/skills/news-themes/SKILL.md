# news-themes: テーマと急な動きの整理

`news-brief` が作った出来事（events.json）とつながり（links.json）を材料に、指定した期間について
1. **基本テーマごとの動き**（何が動いているか・地域の広がり・つながりの連鎖）
2. **急な動き**（カテゴリ × 地域の報道量が平常より大きく増えたところ）
3. **争点テーマ**（既存の争点テーマに当たる出来事と論調・フェーズの見立て、新しい争点テーマの候補）
を整理する。報道そのものは読み直さない（ブリーフの出来事だけを使う）。

## 手順

### 1. 期間を決めて集計する

```sh
uv run python .claude/skills/news-themes/scripts/aggregate_themes.py                                # 最新のブリーフの期間
uv run python .claude/skills/news-themes/scripts/aggregate_themes.py --since 2026-11-01 --until 2026-11-07
```

- 出力: `dist/themes/<ラベル>/aggregate.md`（読む用）と `aggregate.json`
- 対象期間に重なるブリーフが無ければ、先に `news-brief` をその期間で実行するよう提案する
- 急な動きは、ブリーフで覆われた日だけを平常の量の計算に使う（パイプラインの B6 と同じ基準: 直近 14 日の平均の 4 倍超・5 件以上）。
  覆われた過去の日が 7 日未満のものは「参考」。ブリーフが飛び飛びだと平常の量が粗くなる点に注意

### 2. 整理を書く（メインセッションが自分で行う）

`aggregate.md` を読み、必要に応じて各ブリーフの `brief.md`・`events.json`・`links.json` を見て、
`dist/themes/<ラベル>/themes.md` を書く:

```
# テーマ整理 <ラベル>（<since>〜<until> JST、ブリーフ <n> 本、出来事 <n> 件）

## 見取り図
- 期間全体で大きく動いたテーマを 3〜6 点（どのテーマ・どの地域で、何が起きたか）

## 基本テーマごとの動き
### <基本テーマ>（出来事 <n>・報道 <n>）
- 主な流れ 1〜3 点。つながり（原因 → 反応 → 続報…）の連鎖があれば、出来事を時系列で 1 本の線として書く
- 地域の広がり（どこで報じられているか、偏り）
（出来事の無いテーマは省く。「その他」が多い場合は分野の見直しの合図として書き添える）

## 急な動き
- <日> <テーマ> × <地域>: <件数>（平常 <x>、<倍率>）— 何がそれを押し上げたか（該当の出来事）
- 「参考」のものは参考と明記する。履歴が足りない旨も書く

## 争点テーマ
### 既存の争点テーマ
- <名前>: 当たる出来事、見出し・要約から読める論調の偏り（論調の軸に沿って）、フェーズの見立て（根拠つき）
### 新しい争点テーマの候補
- id / 名前 / 親の基本テーマ / 範囲 / 論調の軸（3 つ程度）/ フェーズ（例: 黎明 → 拡大 → 摩擦 → ルール整備 → 定着）/
  候補にした理由（期間内に繰り返し現れ、立場の対立がある出来事）
```

ルール:
- ブリーフの出来事・つながりに書かれていないことは書かない。論調・フェーズは「見出しと要約からの見立て」と明記する
- 出来事を挙げるときは参照（`<ブリーフのラベル>/<出来事 id>`）を添える

### 3. ユーザーへ

見取り図と急な動きをチャットに貼り、`themes.md` のパスを伝える。
新しい争点テーマの候補があれば挙げ、**DB に登録するかはユーザーに確認してから**:

```sh
uv run news theme add <id> --name "<名前>" --scope "<範囲>" --parent <基本テーマ id> --stance "推進,慎重,反対" --phases "黎明,拡大,摩擦,ルール整備,定着"
```

（基本テーマの id は aggregate.md の末尾にある。登録した争点テーマは次回以降の集計で「既存の争点テーマ」に出る）

## メモ

- 整理の結果はファイル（dist/themes/）にだけ残し、DB の spikes・event_themes・report_stances には書かない
  （例外は、ユーザーが承認した争点テーマの定義の登録だけ）
- カテゴリはブリーフ作成時の振り分け。同じ報道が複数のブリーフに入っているときは新しいブリーフの判定を使う
