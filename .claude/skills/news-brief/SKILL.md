# news-brief: 期間を指定した簡易ブリーフ（出来事とつながりまで）

収集した報道の **見出しと抜粋だけ** を使い、指定した期間について
1. 報道を **出来事** にまとめ（地域ごと → 地域をまたいで統合）
2. 出来事どうしの **つながり** を付け
3. 全体の要点・主な出来事・地域 × カテゴリ別の要約を書く。

全文（report_texts）は使わない（1 日 ~500 万トークンになり一括では入らないため。見出し + 抜粋なら ~20 万トークン）。
**ここまでがこのスキルの範囲**。テーマごとの動き・急な動き・争点テーマの整理は、ブリーフがたまってから
任意のタイミングで `news-themes` スキルで行う。

## 手順

### 0. 期間を決める

ユーザーの指定から期間を決める（JST の日付で受け取るのが基本）。指定が無ければ DB の最新の収集日時から 24 時間。

- 「今日」「昨日」→ その JST の日付 1 日、「11/1〜11/3」→ `--since 2026-11-01 --until 2026-11-03`、「この 1 週間」→ 7 日分
- 収集済みの範囲は `sqlite3 data/news.db "SELECT MIN(COALESCE(published_at,fetched_at)), MAX(fetched_at) FROM reports"` で確認する。
  期間が収集済みの範囲から外れていれば、先に `uv run news run-stage collect` を提案する（**実行はユーザーに確認してから**）
- 長い期間（目安 3 日超）は件数が多くなるので、書き出し後の manifest の件数を見て、地域の分割を細かくする（下記）

### 1. 地域ごとに書き出す

```sh
uv run python .claude/skills/news-brief/scripts/export_headlines.py --since 2026-11-01 --until 2026-11-02
uv run python .claude/skills/news-brief/scripts/export_headlines.py --hours 24     # 最新の収集日時から 24 時間
```

- 出力: `dist/briefs/<ラベル>/`（ラベルは 1 日なら JST の日付、複数日なら `<開始日>_<終了日>`）
  - `regions/<地域>.md`（「番号. [媒体 / 国 / 言語] 見出し — 抜粋」）と `regions/<地域>.ids.json`（番号 → report id）
  - `manifest.json`（期間・地域ごとの件数）
- 同じ見出しの転載は 1 本にまとめる。抜粋は 200 字で切る

### 2. 地域ごとに出来事にまとめる（サブエージェントで並列）

件数が 0 でない地域ごとに 1 つずつサブエージェント（general-purpose）を **同じメッセージ内で並列に** 起動する。
プロンプトは下の「地域の出来事化プロンプト」を使い、`{region}` `{input}` `{output}` を埋める
（`{output}` は `dist/briefs/<ラベル>/events/<地域>.json`）。

- **モデルは Sonnet 系を使う**: Agent ツールの呼び出しで必ず `model: "sonnet"` を指定する
- 件数の少ない地域（目安 50 件未満）は 1 つのサブエージェントにまとめてよい（出力は地域ごとに別ファイル）
- 1 地域が 600 件を超えるときは、入力の番号の範囲で 2〜3 つに分けて別々のサブエージェントに渡し、
  最後に 1 つの JSON にまとめる（番号は元の regions/<地域>.md の番号のまま使う）

### 3. 検証と一覧（スクリプト）

```sh
uv run python .claude/skills/news-brief/scripts/build_events.py index dist/briefs/<ラベル> [--prev dist/briefs/<前のラベル>]
```

- サブエージェントの JSON を検証し（番号の範囲・重複・カテゴリ名）、`events_index.md` を書く:
  カテゴリ別の地域の出来事一覧（キー `<地域>-<番号>`）、地域をまたいで似ている「統合の候補」、
  `--prev` を付けたときは前のブリーフの主な出来事
- `--prev` には、期間が直前のブリーフ（`dist/briefs/` で events.json があるもののうち一番新しいもの）を渡す
- 警告が多い地域（どの出来事にも入っていない報道が半分以上、など）は、その地域だけサブエージェントをやり直す

### 4. 出来事の統合とつながり（メインセッションが自分で行う）

この工程はサブエージェントに出さず、**メインセッション（Opus）が自分で行う**（地域をまたぐ同定・因果の判断が要るため）。
`events_index.md` を読み（必要なら `events/<地域>.json` の要約も見て）、`dist/briefs/<ラベル>/curation.json` を書く:

```json
{
  "merge": [["中東-3", "欧州-12", "北米-5"],
            {"members": ["東アジア-1", "北米-9"], "title": "（統合後の見出し。省略可）", "summary": "（統合後の要約。省略可）"}],
  "links": [{"from": "中東-3", "to": "中東-7", "type": "反応", "reason": "…", "confidence": 0.7},
            {"from": "2026-11-01/E0004", "to": "欧州-5", "type": "続報", "reason": "…", "confidence": 0.8}]
}
```

- **統合**: 同じ 1 つの出来事を別の地域の媒体が報じているものをまとめる。候補一覧は文字の重なりで出しているだけなので、
  候補に無い組も見て判断する。**迷ったら混ぜずに分ける**。複数地域にまたがる大きな出来事は、統合後の見出し・要約を書く
- **つながり**: 種類は 原因 / 反応 / 続報 / 激化 / 収束 の 5 つ。向きは 原因 → 結果、元の出来事 → 続報・反応。
  `reason` に根拠（見出し・抜粋から言えること）を 1 文、`confidence` に 0〜1。
  見出しと抜粋から言えるものだけを付ける（推測でつなげない）。主な出来事（報道の多いもの）を中心に、目安 10〜40 本
- 前のブリーフの出来事への続報・反応は、端を `<前のラベル>/<出来事 id>` にする

続けて `dist/briefs/<ラベル>/overview.md` を書く:

```
## 全体の要点
- 地域をまたぐ大きな動きを 5〜8 点（どの地域で報じられているか、つながりがあれば「◯◯ への反応」のように添える）

## カテゴリ別の横断
基本テーマごとに、複数地域にまたがる話題だけを 1〜3 行で
```

### 5. 組み立て（スクリプト）

```sh
uv run python .claude/skills/news-brief/scripts/build_events.py finalize dist/briefs/<ラベル>
```

- `events.json`（統合後の出来事: id・見出し・要約・カテゴリ・地域・report id・媒体・国・言語・重要度）と
  `links.json`（つながり）を書き、`brief.md` を組み立てる:
  見出し → overview.md → 主な出来事 10 件（重要度順・同じ地域は 3 件まで・つながりを添える）→ つながり一覧 →
  地域別（地域の要点とカテゴリごとの出来事。1 カテゴリ 6 件、残りは「ほか」）→ この要約について
- 重要度 = 報道数 × 多様さ（媒体・国・言語の数の平均）×（1 + 0.25 × つながりの数）
- `link を捨てた` などの警告が出たら curation.json を直して finalize をやり直す

最後にユーザーへ: 全体の要点と主なつながりをチャットに貼り、`brief.md` のパスを伝える。
ブリーフがいくつかたまったら `news-themes` でテーマと急な動きを整理できることを一言添える。

## 地域の出来事化プロンプト

```
あなたはニュースの編集者です。ファイル {input} に、{region} の情報源から集めた報道の見出しと抜粋が
「番号. [媒体 / 国 / 言語] 見出し — 抜粋」の形で並んでいます（言語は混在）。これだけを根拠に、
同じ出来事を報じた報道を 1 つの「出来事」にまとめ、日本語の JSON を {output} に保存してください
（Write ツール。他のファイルは作らない・変更しない）。

JSON の形:
{
  "points": "この地域の要点（2〜4 文。この期間に何が起きたか）",
  "events": [
    {
      "title": "出来事の見出し（日本語 1 行、40 字以内）",
      "summary": "出来事の要約（1〜2 文）",
      "when": "いつ（抜粋から分かれば。例 2026-11-01、11月1日。分からなければ空文字）",
      "where": "どこで（国・都市など。分からなければ空文字）",
      "who": ["主な人物・組織"],
      "categories": ["基本テーマ（1〜2 個。最初が主分類）"],
      "reports": [この出来事を報じた報道の番号],
      "about": "他地域の出来事なら対象の地域や国（例: 中東、ウクライナ）。この地域の出来事なら空文字"
    }
  ]
}

ルール:
- 出来事 = 同じ時期・同じ場所・同じ当事者についての 1 つの出来事。同じ話題でも別の出来事（例: 別の日の別の攻撃）は分ける。
  迷ったら混ぜずに分ける。1 本の報道だけの出来事もそのまま 1 件にする
- 1 つの報道はちょうど 1 つの出来事にだけ入れる（同じ番号を 2 回使わない）。
  見出しと抜粋から内容が判断できない報道（広告・目次・意味の取れないもの）は、どの出来事にも入れなくてよい
- 基本テーマは次の 14 個から選ぶ（この表記のまま）:
  国際関係・外交 / 紛争・安全保障 / 政治・選挙 / 経済・市場 / 企業・産業 / テクノロジー・AI / 科学・宇宙 /
  気候・環境・エネルギー / 災害・事故 / 健康・医療 / 社会・事件 / エンタメ・カルチャー / スポーツ / その他
- events は重要な順（報じた媒体の数・社会的影響）に並べる
- 見出し・抜粋に書かれていないことは書かない。数字・固有名詞は原文どおり。推測は書かない
- 終わったら、保存したパス、出来事の数、どの出来事にも入れなかった報道の数だけを返す（JSON の中身は返さない）
```

## メモ

- 地域の割り当ては情報源の国（`src/world_events/regions.py`）。INTL・国際機関は「その他」
- 出来事・つながり・カテゴリは **ファイル（dist/briefs/）にだけ** 残し、DB の events / links / event_themes には書かない
  （パイプラインの B2・B4 の結果と混ぜないため）。カテゴリは要約時の振り分けで、B4 の結果ではない
- 出力の `dist/` は git 管理外
