# world-events

世の中の出来事を、記事の「点」ではなく **出来事のまとまり・テーマ・時間の流れ** で把握するためのシステム。
世界各地の報道を集めておき、欲しいときに期間を指定して、同じ出来事を報じた記事を 1 つにまとめ、出来事どうしをつなぎ、
テーマに振り分けて、「この期間になにが起きたか」「いつもと違う動きはどこか」「どう変わってきたか」を見られる形にする。

CurioSpector とは独立しており、その Vault や LanceDB には依存しない。

---

## 1. 概念

```
情報源 ──集める──▶ 報道 ──まとめる──▶ 出来事 ──振り分ける──▶ テーマ
                                       │                        │
                                       └── つながり ──┘          ├─ 急な動き（日次）
                                                                └─ 定点記録（月次）
                                ダイジェスト（日次）◀── 出来事・急な動き・通知
```

### 情報源（source）

報道を取りに行く先。RSS フィード・サイトマップ・ニュース一覧ページ・GDELT の検索条件のいずれか。
それぞれ **媒体名・国・言語** を必ず持ち、何日おきに取りに行くかを決めておく。

- 追加・変更・停止・再開はすべて **変更履歴** に残る（誰が: 人の CLI / 画面からの依頼 / 自動、理由付き）
- 取得に **5 回続けて失敗すると自動で停止** し、その日のダイジェストで知らせる
- 国から **地域**（北米・欧州・中東・東アジア など 10 地域 + その他）が決まる。国際機関・国際媒体は「その他」

### 報道（report）

1 本の記事。見出しと抜粋（最大 1000 字）、媒体・国・言語、公開時刻を持つ。

- 同じ URL、または見出し + 抜粋が同じもの（転載）は **1 本として扱う**
- 1 週間より古い記事は取り込まない
- 本文が取れたものは本文も保存するが、**本文は 30 日で捨てる**（見出し・抜粋・要点は残る）
- 記事ごとに日本語の見出し・要点・固有表現・数値・出来事の時刻を抜き出す（L1）。
  このとき **元の記事に無い固有名詞や数値は消す**（作り話を残さない）

### 出来事（event）

複数の媒体・国が報じている「同じ 1 つの出来事」のまとまり。報道は **ちょうど 1 つの出来事にだけ属する**。

- 見出し・要約・いつ・どこで・誰が、報道の数、報じた国の数、主な地域を持つ
- 要約は、媒体と国が偏らないように選んだ最大 6 本の報道から作る。報道が 1 本だけなら記事の見出しをそのまま使う
- 報道が 2 倍に増えた、または新しい国の報道が加わったら要約を作り直す
- 要約に元の報道に無い数値が出たら作り直し、それでもだめなら代表の記事の見出しで代える
- **重要度** = 報道の多さ × 報道の多様さ（媒体・国・言語の数）× つながりの多さ ＋ 争点テーマに属していれば加点
- **人が直した出来事は確認済みになり、以後は自動処理で上書きしない**

### テーマ（theme）

出来事を分類する枠。2 種類ある。

| 種類 | 何か | 振る舞い |
|---|---|---|
| 基本テーマ | 世の中を広く覆う 13 の分野 + 「その他」 | すべての出来事が **必ず 1 つ以上** に属する。どれにも当たらなければ「その他」。「その他」が増えたら分野の見直しの合図 |
| 争点テーマ | 基本テーマの下に置く、追いかけたい具体的な論点（例: 生成 AI の著作権と規制） | 親の基本テーマに属した出来事の中から判定する。**論調の軸**（例: 推進 / 慎重 / 反対）と **フェーズ**（例: 黎明 → 拡大 → 摩擦 → ルール整備 → 定着）を持ち、属する出来事の各報道に論調を付ける |

基本テーマ: 国際関係・外交 / 紛争・安全保障 / 政治・選挙 / 経済・市場 / 企業・産業 / テクノロジー・AI /
科学・宇宙 / 気候・環境・エネルギー / 災害・事故 / 健康・医療 / 社会・事件 / エンタメ・カルチャー / スポーツ / その他

- テーマの名前や範囲を書き換えると **新しい版** ができ、古い版も残る
- 出来事をテーマに振り分けたときは **判定に使った版を記録** し、テーマが改版されても自動では判定し直さない
  （過去の分類が後から黙って変わらないようにするため）

### つながり（link）

出来事と出来事の関係。種類は **原因・反応・続報・激化・収束** の 5 つで、根拠の説明と確からしさを持つ。
ダイジェストでは「◯◯ の続報」のように前の出来事を添える。人が確認・却下でき、確認したものは上書きされない。

> パイプラインにはつながりを自動で作る段階はまだ無い（入れ物と、人の確認・却下の受け付けだけがある）。
> いまは簡易ブリーフ（2 章）で Claude が付けており、結果はブリーフの `links.json` にある。

### 急な動き（spike）

テーマごとの 1 日の報道量が、直近 14 日の平均を大きく超えたときの記録。

- テーマ全体と、基本テーマ × 地域（例: 災害・事故 × 東南アジア）の両方で見る
- 基準は基本テーマで平常の 4 倍、争点テーマで 2.5 倍、かつ 5 件以上
- 履歴が 7 日に満たないうちは平常の量が分からないので検知しない

### ダイジェスト（digest）

パイプラインが 1 日 1 本作る、その日の見取り図（日付は JST）。いまは定期実行していないので、簡易ブリーフ（2 章）が代わりを務める。

- **主な出来事 10 件**: 前回のダイジェスト以降に現れた出来事を重要度順に並べる。
  ただし **同じ地域は最大 3 件** にし、溢れた枠は他地域の上位で埋める（一地域の話題で埋まらないように）
- **基本テーマごとの見出し**: 各テーマ最大 3 件
- **急な動き** の一覧
- **通知**: 自動停止した情報源、スキップ・失敗した処理段階
- 静的な HTML ページとしても書き出す

### 定点記録（snapshot）

テーマごとに月に 1 回とる記録。報道量、出来事の数、国・地域・言語ごとの内訳、主な出来事 5 件、
（争点テーマなら）論調の分布（全体・国別・言語別）を残す。月をまたいで並べて変化を見るためのもの。

> 「この月に何が変わったか」の要約と、フェーズの判定を入れる欄はあるが、現状は埋めていない。

### 変更依頼（change request）

閲覧側の画面から出された「情報源を追加・停止したい」「テーマを直したい」「このつながりは正しい / 誤り」
「この出来事のテーマを付け替えたい」といった依頼。**正本は Mac 側の DB だけ** で、依頼はパイプラインの実行の最初に
検証して取り込む。通らない依頼は理由を付けて却下し、他の処理は止めない。

## 2. 振る舞い

小さく始めるため、**定期実行（毎晩の自動処理）はしない**。欲しくなったときに、期間を指定して手で回す。
流れは 2 段で、それぞれ別のスキルとして任意のタイミングで実行する。

```
（必要なら）収集 ──▶ 簡易ブリーフ（news-brief） ──ブリーフがたまったら──▶ テーマ整理（news-themes）
                     期間を指定して                                       期間を指定して
                     報道 → 出来事 → つながり → 要約                       テーマごとの動き・急な動き・争点テーマ
```

### 簡易ブリーフ（news-brief スキル）— 出来事とつながりまで

「11/1〜11/3 のブリーフを作って」のように **期間（JST の日付）を指定** して実行する。指定が無ければ直近 24 時間。
集めた報道の **見出しと抜粋だけ** を使い、Claude が次の順に処理する（`.claude/skills/news-brief/`）。

| 順 | やること | 誰が |
|---|---|---|
| 1 | 期間の報道を地域ごとに書き出す（同じ見出しの転載は 1 本に） | スクリプト |
| 2 | 地域ごとに、同じ出来事を報じた報道を **出来事** にまとめ、見出し・要約・いつどこで誰が・カテゴリ（基本テーマ）を付ける。**迷ったら混ぜずに分ける** | サブエージェント（地域ごとに並列） |
| 3 | 地域をまたいで同じ出来事を **統合** し、出来事どうしの **つながり**（原因・反応・続報・激化・収束、根拠と確からしさ付き）を付ける。前のブリーフの出来事への続報もつなぐ | メインセッション |
| 4 | 重要度（報道の多さ × 多様さ × つながりの多さ）を計算し、ブリーフを組み立てる | スクリプト |

- 出力は `dist/briefs/<ラベル>/`（ラベルは 1 日なら JST の日付、複数日なら `<開始日>_<終了日>`）
  - `brief.md`: 全体の要点 → カテゴリ別の横断 → 主な出来事 10 件（同じ地域は 3 件まで、つながりを添える）→ つながり一覧 → 地域別
  - `events.json`（出来事と、それを報じた report id）・`links.json`（つながり）: 次のテーマ整理の材料
- 期間がまだ収集していない範囲なら、先に収集（`news run-stage collect`）を確認のうえ実行する
- 出来事・つながり・カテゴリはファイルにだけ残し、DB の events / links / event_themes には書かない
  （見出しと抜粋から Claude がまとめたもので、パイプラインの B2・B4 の結果とは別物のため）

### テーマ整理（news-themes スキル）— テーマ・急な動き・争点テーマ

ブリーフがいくつかたまったら、任意のタイミングで期間を指定して実行する（`.claude/skills/news-themes/`）。
ブリーフの出来事とつながりだけを材料にし、報道は読み直さない。

- **基本テーマごとの動き**: 出来事の数・報道量・地域の広がり、つながりの連鎖（原因 → 反応 → 続報…）を 1 本の流れとして書く
- **急な動き**: カテゴリ全体と カテゴリ × 地域 の 1 日の報道量を、直近 14 日の平均と比べる（基本テーマで平常の 4 倍超・5 件以上）。
  平常の量はブリーフで覆われた日だけから計算し、覆われた日が 7 日に満たないうちは「参考」として出す
- **争点テーマ**: 既存の争点テーマに当たる出来事と、論調の偏り・フェーズの見立て。繰り返し現れて立場が分かれる話題は
  新しい争点テーマの候補として出し、**登録はユーザーが承認してから**（`news theme add`）
- 出力は `dist/themes/<ラベル>/themes.md`（材料は同じ場所の `aggregate.md` / `aggregate.json`）

### 人の手が入るところ

- 情報源とテーマの定義は人が決める（CLI、または閲覧側からの変更依頼）
- いつ・どの期間でブリーフやテーマ整理を作るかは人が決める
- 処理の閾値や重要度の式はコードの定数として持つ（変えた履歴が git に残るように）
- 時刻はすべて UTC で持ち、「1 日」「1 か月」の区切りだけ JST で数える

### パイプライン（いまは定期実行していない）

1 章の概念のうち、LLM で記事ごとに抽出（L1）→ 出来事化（B2）→ 要約（L3）→ テーマ振り分け（B4）→ 急な動き（B6）→
ダイジェスト（B7）→ 定点記録（B5）と進める段階はコードとして残してあり、`news run-stage <段階>` で 1 段階ずつ動かせる。
いまは収集（B1）だけを使い、それ以降は上の 2 つのスキルで代わりに行っている。
パイプラインを使うときの LLM との付き合い方:

- 要約や判定に使う LLM（以下、要約 LLM）は、開発中は手元の Ollama、本番は Cloudflare Workers AI を使う。
  **本番の処理を手元のモデルに逃がすことはしない**（違うモデルの出力が正本に混ざるのを避ける）
- 要約 LLM が応答しない・混んでいる・使用量の上限を超えたときは、その段階を **スキップ** にして未処理を残し、
  次の実行で続きから処理する
- 使いすぎの防止: 1 回の実行の使用量が **前回の 2 倍を超えたら止める**
- 同じ入力・同じモデル・同じ指示への答えは保存して使い回す（環境やモデルが違えば別物として扱う）
- 意味の近さを測る埋め込みは、開発・本番とも同じもの（bge-m3）を使う。変えると近さの基準がずれるため
- 出力の固有名詞・数値は、入力にあるかを規則で照合する（作り話の防止）
- モデルや指示を替えるときは、評価セットで JSON の成立率・作り話の率・速度を測ってから決める（`news bench`）
- 出来事・テーマの付与・つながりを人が直すと「確認済み」になり、自動処理はそれを上書きしない

## 4. 動かし方

```sh
uv sync --extra extract --extra embed
uv run news db-migrate

uv run news source list                 # 情報源（add / update / disable / enable / history / import / export）
uv run news theme list                  # テーマ（add / update / history）

uv run news run-stage collect           # 収集（ブリーフの前に、必要なときだけ）

# 簡易ブリーフ・テーマ整理は Claude Code で「11/1〜11/3 のブリーフを作って」「テーマを整理して」と頼む
# （news-brief / news-themes スキル。手順は各 SKILL.md）

# パイプライン（いまは定期実行していない）
uv run news run-daily                   # 全段階をまとめて 1 回
uv run news run-stage <段階>            # 1 段階だけ（requests / collect / embed / l1 / b2 / l3 / b4 / importance / b6 / b7 / prune / publish）
uv run news fetch-bodies                # 本文が無い報道の本文を後から取りに行く
uv run news run-monthly                 # 月初なら前月の定点記録（--month YYYY-MM で指定）
uv run news digest                      # 最新のダイジェストを表示

uv run news eval sample --task l1 -n 100
uv run news bench --env local           # 要約 LLM の評価

uv run pytest                           # テスト（LLM と埋め込みは偽物に差し替え）
```

### 閲覧の画面（Cloudflare）

```sh
uv run news publish --apply             # dist/ のブリーフ・テーマ整理を取り込み、前回以降の差分を D1 に写す
uv run news requests pull --apply       # 画面から出された変更の依頼を取り込んで反映する
uv run news view [クエリ名] -p k=v      # 画面と同じクエリ（contracts/queries.sql）を手元の DB に流す
```

ローカルで全体（画面 + Claude Code 用の MCP）を動かす:

```sh
docker compose up -d --build            # 画面 http://localhost:8788 ・ MCP http://localhost:8765/mcp（.mcp.json に登録済み）
```

構成・初回の配信手順・MCP のツールは `docs/webui-and-mcp.md`。

環境（`NEWS_ENV=local|prod`）や接続先の設定は `.env.example` を参照。
